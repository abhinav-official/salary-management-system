## Deployment and independent calculation contract

`tools/acceptance_reference.py` reads the sample's OOXML directly with the standard library and imports no production salary, schema, query, generator or validation functions. It uses Fraction and integer half-up rounding rather than the application's Decimal implementation. It recalculates every summary value, compa bucket/percentage and every identity-excluded peer median/percentage. The peer reference deliberately sorts each target's remaining peers anew rather than reusing production's optimized positions algorithm.

`tools/acceptance_compose.py` rebuilds both images without cache, creates fresh source and restore volumes, loads every band exactly, previews/confirms all sample rows through the same-origin web proxy, checks full and filtered CSV and directory pages, and runs the reference comparison. It checks all tables' sorted-content SHA-256 digests and counts over down/up and recreation. Its online SQLite backup is taken while a committed marker is held in WAL by an active reader; restore into a separate project must retain that marker and every saved table digest. Restored CSV, analytics, equity and receipt must equal the source responses. Unauthorized endpoints return 401; API outage returns 503 and restart recovers persisted session/data and safe confirmation retry. No primary deployment volume or `.env` is used.

`tools/smoke_compose.py` additionally verifies runtime web mounts, direct API rejection, login origin/CSRF/cookies, loader conflict, band deletion without reseeding, stale revisions, CRUD and stale preview atomicity. `tools/browser_compose.py` exercises real forms, keyboard focus/confirmations, search/filter/page changes, loading/empty/error/retry states, band effects, all preview errors, full-size uploads/downloads, lost-response retries, summaries/equity refresh and restart persistence. These are automated browser checks, not unperformed manual claims.
